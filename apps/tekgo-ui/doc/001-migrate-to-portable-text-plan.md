# Migrate from MDX to Portable Text

This plan outlines the steps to completely migrate the `tekgo-ui` project's content layer from MDX to Portable Text (JSON AST).

## User Review Required

> [!WARNING]  
> **Data Migration Complexity**
> Converting your existing 14 `.mdx` files to Portable Text requires a custom parser script. Because MDX allows arbitrary React code (like `<TOCInline />` and `<video controls>`), the script will attempt to map these to custom Portable Text blocks. Some manual cleanup of the generated JSON files may be required if there are edge-case React components in older posts.

> [!IMPORTANT]  
> **Computed Fields (TOC and Reading Time)**
> Currently, `contentlayer.config.ts` calculates the Table of Contents (TOC) and reading time by parsing raw Markdown. With a JSON AST, we will need to rewrite these extraction functions to traverse the Portable Text JSON array instead.

## Open Questions

- **Frontmatter vs Pure JSON**: We can either store the new posts as `.json` files (containing both metadata and the body array) or as `.yaml` files. I recommend `.json` for native compatibility with Contentlayer's `data` type. Does pure `.json` work for you?
- **Authoring Experience**: How do you plan to write new posts going forward? Portable Text is typically generated by a headless CMS (like Sanity). If you are writing them locally, editing raw Portable Text JSON by hand is not ergonomic. You might need a local rich-text editor or a script that continues to convert Markdown to JSON on the fly. 

## Proposed Changes

---

### 1. Dependencies

#### [MODIFY] `package.json`
- **Add**: `@portabletext/react` (for rendering the JSON AST to React).
- **Add (Dev)**: `mdast-util-to-portable-text` and `remark-parse` (to help build the one-off migration script).

---

### 2. Contentlayer Configuration

#### [MODIFY] `contentlayer.config.ts`
- Change `contentType: 'mdx'` to `contentType: 'data'` for both `Blog` and `Authors`.
- Change `filePathPattern` from `**/*.mdx` to `**/*.json`.
- Refactor the `readingTime` and `toc` computed fields. Instead of running `reading-time` and `extractTocHeadings` on raw text, we will write a small utility to extract text and headings directly from the Portable Text JSON array.
- Remove all `mdx` specific configurations (`remarkPlugins`, `rehypePlugins`).

---

### 3. Rendering Engine

#### [NEW] `components/PortableTextRenderer.tsx`
- Create a new component wrapping `<PortableText />` from `@portabletext/react`.
- Map Portable Text block types to your existing Tailwind/React components:
  - `block`: Map headings (`h1`-`h6`) and paragraphs.
  - `image`: Map to Next.js `Image`.
  - `code`: Map to a custom PrismJS or generic code highlighter component (replacing `rehype-prism-plus`).
  - `math`: Map to a KaTeX renderer component (replacing `rehype-katex`).
  - `TOCInline`: Map to your existing TOC component.

#### [MODIFY] `app/blog/[...slug]/page.tsx`
- Remove `import { MDXLayoutRenderer } from 'pliny/mdx-components'`.
- Import and use the new `<PortableTextRenderer content={post.body} />`.

---

### 4. Data Migration

#### [NEW] `scripts/migrate-to-portable-text.mjs`
- A one-off script to read all files in `data/blog/` and `data/authors/`.
- Uses `gray-matter` to extract metadata (title, date, tags).
- Parses the Markdown body into an MDAST (Markdown AST).
- Converts the MDAST to Portable Text blocks.
- Writes the final output to a corresponding `.json` file.

#### [DELETE] `data/blog/*.mdx` & `data/authors/*.mdx`
- After running the script and verifying the `.json` output, we will delete the legacy MDX files.
