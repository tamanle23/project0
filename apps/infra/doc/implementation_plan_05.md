# PostgreSQL Infrastructure Implementation Plan

To support your backend data storage requirements, we need to introduce PostgreSQL into our GitOps architecture. Following best practices, we will use an **in-cluster database for local development** and a **managed cloud database (like AWS RDS) for staging/production**.

## User Review Required

> [!IMPORTANT]
> The plan proposes injecting PostgreSQL entirely via Kustomize environment overlays:
> 
> 1. **Local**: Kind will spin up a standard PostgreSQL `StatefulSet`.
> 2. **Production/Staging**: Crossplane will provision an AWS RDS instance and securely write the connection credentials into a Kubernetes `Secret`.
> 
> Do you approve this database architecture split?

## Proposed Changes

### 1. Local Database Environment (`overlays/local/`)
We will add an in-cluster PostgreSQL database exclusively for local development using Kind.
- **[NEW] `apps/infra/k8s/overlays/local/postgres.yaml`**: A StatefulSet (using `postgres:15-alpine`), a Service (port 5432), and a basic Secret containing default developer credentials (`postgres`/`password`).
- **[NEW] `apps/infra/k8s/overlays/local/backend-patch.yaml`**: A Kustomize patch that injects standard Spring Boot database environment variables (`SPRING_DATASOURCE_URL`, etc.) into the `backend` deployment, pointing to the local `postgres:5432` service.
- **[MODIFY] `apps/infra/k8s/overlays/local/kustomization.yaml`**: Include the new files.

### 2. Crossplane Database Blueprints (`crossplane/`)
We will create Crossplane blueprints for provisioning cloud-managed databases (e.g., AWS RDS).
- **[NEW] `apps/infra/crossplane/postgres-xrd.yaml`**: An XRD named `XPostgreSQLInstance` allowing us to request a database specifying storage size and version.
- **[NEW] `apps/infra/crossplane/postgres-composition-aws.yaml`**: A Composition that maps `XPostgreSQLInstance` to an AWS RDS `Instance` resource, configuring it to automatically generate passwords and publish the connection details to a standard Kubernetes Secret.

### 3. Production & Staging Claims (`overlays/production|staging/`)
- **[NEW] `apps/infra/k8s/overlays/production/db-claim.yaml`**: Requests a production-grade Crossplane PostgreSQL instance (e.g., 50GB storage).
- **[NEW] `apps/infra/k8s/overlays/staging/db-claim.yaml`**: Requests a staging-grade Crossplane PostgreSQL instance (e.g., 20GB storage).
- **[NEW] `apps/infra/k8s/overlays/*/backend-patch.yaml`**: Configures the `backend` Deployment in these environments to extract its `SPRING_DATASOURCE_*` connection strings securely from the Kubernetes Secret dynamically generated by Crossplane.
