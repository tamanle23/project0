## 2024-05-18 - Prevent Unnecessary Re-Renders in `useSidebarData`
**Learning:** `useSidebarData` in `apps/console` returned a completely new object containing deeply nested navigation arrays on every single render. Since this hook is called by primary layout components like `AppSidebar` and `CommandMenu`, it caused significant unnecessary re-renders across the main layout tree.
**Action:** When creating custom hooks that return large configuration objects or arrays of UI items, always wrap the return value in `useMemo` (e.g., `useMemo(() => ({ ... }), [deps])`) to maintain referential equality across renders unless the dependencies change.

## 2024-05-24 - Debouncing React Router Table Filters
**Learning:** In the `@project0/console` frontend, the `DataTableToolbar` was directly pushing every keystroke from its search input into the `useTableUrlState` hook, which in turn calls `navigate` from React Router. This is a significant performance bottleneck because it causes a full route re-evaluation, URL update, and potential data re-fetch on every single keypress. Furthermore, when synchronizing an internal state (`searchValue`) with external state (the URL table filter), using `useEffect` with a simple comparison `tableVal !== debouncedSearchValue` creates infinite loops because the `useEffect` runs *after* render when `tableVal` might still be stale.
**Action:** When connecting text inputs to React Router URL state, always wrap the input with a local state and debounce the synchronization using `useDebounce`. When reconciling external state (like a URL filter) with internal local state, track the *previous* incoming external value to differentiate between an internal change (the user typing) and an external reset (the user clicking a "Reset" button).
